# Atomic implementation tasks

- **T-1 — Freeze the execution inventory.** Trace every subprocess and external effect in `worker.py`, `runtimes.py`, `threat_models.py`, and delivery paths; identify stage-specific checkout and credential needs. **Depends on:** none. **Done when:** each launch path maps to a guest command or trusted supervisor operation.
- **T-2 — Define isolation policy and protocol schemas.** Specify validated `IsolationPolicy`, `JobEnvelope`, `GuestResult`, and `IsolationRecord`, including limits and rejection rules. **Depends on:** T-1. **Done when:** malformed or missing policy and oversized guest output have explicit fail-closed behavior.
- **T-3 — Build the pinned guest image.** Install both approved CLI adapters, Git, `gh`, verifier, and required check dependencies without host mounts or runtime package downloads. **Depends on:** T-1. **Done when:** image digest and dependency inventory are reproducible.
- **T-4 — Implement the VM launcher and lifecycle.** Create one isolated guest per claim with resource limits, private protocol channel, complete descendant termination, and verified teardown; remove host command fallback. **Depends on:** T-2, T-3. **Done when:** no issue-driven command can run if VM setup fails.
- **T-5 — Enforce outbound policy.** Implement the no-direct-route guest network and fence-bound allowlist proxy; publish measured destination profiles for both providers and GitHub. **Depends on:** T-2, T-4. **Done when:** unapproved, private, and host destinations are denied independently of guest behavior.
- **T-6 — Implement per-job credential grants.** Issue and revoke only active provider and repository credentials through temporary guest storage; ensure Git remotes and checkpoints contain no tokens. **Depends on:** T-4, T-5. **Done when:** unrelated and administrator credentials are absent from guest inspection and grants end on teardown or claim loss.
- **T-7 — Move job execution into the guest.** Route worktree creation, both `AgentRuntime` adapters and authentication checks, Git/`gh`, required checks, and verifier execution through the guest protocol. Handle the separate threat-model repository as the sole active checkout for its stage. **Depends on:** T-4, T-6. **Done when:** the supervisor performs no repository-driven CLI or verifier execution.
- **T-8 — Add bounded checkpoint recovery.** Save and restore active worktree state with repository, ticket, revision, and digest checks; preserve valid interrupted files across disposable guests and reject cross-job imports. **Depends on:** T-4, T-7. **Done when:** pause, restart, and retry retain authorized progress without sharing another job's files.
- **T-9 — Bind lifecycle to isolation evidence.** Persist trusted boundary records and integrate VM shutdown, grant revocation, checkpointing, heartbeat loss, and fencing with claim, yield, and completion. **Depends on:** T-5 through T-8. **Done when:** a stale guest cannot retain network grants or submit accepted completion, and failures are auditable without secrets.
- **T-10 — Preserve delivery and security gates.** Confirm current-revision root-model verification and approval before engineering, local checks inside the guest, idempotent GitHub side-effect recovery, and existing opt-in plus protection checks for merging. **Depends on:** T-7 through T-9. **Done when:** the normal lifecycle cannot bypass an existing gate.
- **T-11 — Add focused automated tests.** Cover policy, protocol, grants, checkpoint lineage, cancellation, fencing, and both provider routes. **Depends on:** T-2, T-5 through T-10. **Done when:** each fail-closed path has a regression test.
- **T-12 — Run deployment boundary tests.** Execute hostile issue and repository fixtures against the intended Linux worker deployment, including filesystem, process, credential, and egress canaries, plus restart and retry. **Depends on:** T-11. **Done when:** denial events and unchanged canaries are captured as reviewable evidence.
- **T-13 — Run normal-ticket staging and document operations.** Complete approved stages, checks, verifier, and PR handoff inside disposable guests; record deployed image, policy and proxy digests, credential scopes, cleanup, and residual risk. **Depends on:** T-12. **Done when:** the ticket has reproducible deployment and usability evidence.
- **T-14 — Reconcile the threat model and issue.** Link implementation and deployment evidence to issue #1, confirm `ticketLink`, update control status in Bturbs/Threat-Models, and run root-model verification. **Depends on:** T-13. **Done when:** evidence supports the recorded status; leave `fullyMitigated: false` if any material gap remains.
